# Watching a delayed trial response — v1

Freeze product source/patch, published binaries, this method, fixture and runner
before the first native window launch. Run one case once in Anode with its lease
identity in the process environment. Retain failures without replacement runs.
Use the shared MCP API and automatic jobs; no manually inspected screenshots.

The owned 600x220 WinForms fixture allocates 32 MiB and randomizes a naturally
aligned F32 field in the upper half. It stores half the displayed number. Normal
set commands change both memory and cached display text. A trial memory write
alone does not redraw the numeric display. A foreground Space key refreshes the
cached text from the field; no memory write is performed by that event. The
separate fixture oracle records field identity, raw-derived value, displayed
text and delivered Space count. Oracle addresses/representations are never
supplied to Reversebolt. They are used only for independent fixture assertions.

Connect with a one-MiB ordinary budget and no optional model. Collect one
initial value 50, then use Follow changes with selection values 20,80,30,70.
The product must select areas and schedule its sixteen fresh observations.
Use the fixed fresh values recorded in the manifest. Keep all original frame
identities, selection witnesses, budgets and source images. Verify separately
that the known fixture field was excluded initially, retained by selection and
frozen with four fresh agreements. This is an owned-window workflow test, not
independent-game acceptance or a general recall measurement.

Among OCR checks ordered by track ID, select the first candidate in original
order with exactly four agreeing outcomes. Request current OCR plus 10 once.
No fallback, oracle-driven candidate choice or forced write. The prepared patch
must address the known fixture field; otherwise retain a failed case. Apply
once, retaining its automatic immediate observation. Require written bytes and
the unchanged display. Start a three-observation watch at two-second intervals,
using the exact current phase/count and job authority envelope.

After the first watch observation, send one native Space press held 120 ms.
Check exact foreground HWND/PID and child session before sending; always release
the key. Confirm exactly one fixture event, never replay an uncertain input.
Require no response on the first watch image and the requested value on the
next two, with complete byte-persistence evidence and sampled Space context.
Input samples alone do not establish that a game consumed a key; the fixture's
own event receipt supplies that independent check here.

Attempt guarded restoration once. Its immediate observation must retain the
old displayed test value until another event. Start two restoration observations
at two-second intervals, send one Space after the first, and require the second
to display the original value with matching restoration bytes. Retain all seven
post-edit/restoration observations plus the baseline, including nonresponses.

Do not add writes, try other candidates, mutate the display through the oracle,
or adjust timing/inputs after outcomes. On exceptions, inspect actual state and
attempt restoration once only for a confirmed written trial if restoration has
not already been attempted. Preserve uncertain or refused outcomes. Close only
owned processes and release Anode. Source hashes, job completion, image hashes,
byte receipts, cursor progression and sampled/delivered inputs will be audited
after execution, separately from the frozen method.

A delayed numeric response does not establish general gameplay authority,
hidden-effect scope, complete rollback, or behaviour across restarts. Production
does not inject inputs. Its watch remains an explicit, bounded observation job
shared by the desktop and agents, with pause/stop/takeover and no automatic replay.
