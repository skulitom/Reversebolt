game-specific profile to select a comparison. Review only setup/menu images.

2/4/8/10, as in the prior observation experiment. These four setup inputs are
known evaluator actions, not learned meanings. All subsequent comparison input
must be executed by the product. Do not review measurement images, tune prompts
or substitute a preferred field after seeing the result.

Use the installed local model and automatic attach. The product selects types,
gives each type a small independent question budget, and derives a four-step
sequence and hold bounds from retained key samples. Call plan_runtime_comparisons
and take its next choice unchanged. Use at most two comparisons, each with fresh
test/change IDs, six baseline images, the bounded proposed edit, six changed
images, guarded restoration and six recovery images. Stop/abstention and failed
or inconclusive measurements are valid outcomes, never retried in this context.

Check that the planner retains each outcome and does not propose the same tested
choice again. Preserve exact hypotheses, input estimates, action receipts and
comparison frames. Check recovery before restarting the owned headless engine,
then verify retained evidence and no live target or automatic replay. On failure,
stop the test and restore a known written trial through the existing guarded API;
retain uncertainty without a forced write. Leave the game open if recovery is
unresolved so it can be inspected before cleanup.

Close owned processes and the game only after recovery is settled. Audit user
saves, helpers and input workers, and release Anode. A rendered response contrast
does not establish a gameplay name, physical quantity, actor scope, world rollback
