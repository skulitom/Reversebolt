# Change-based search on independent games — v1

Freeze this method, runner, oracle/scorer/input files, original upstream file
hashes and the published Reversebolt 114033 binary hashes before either launch.
Run fresh owned browser profiles for original 2048 then Javascript Tetris, once
each, inside Anode. These are exposed development games, not withheld acceptance.
Keep all failures, refusals and abstentions; no replacement runs or selection
changes after results. Leave the user's running desktop preview alone.

Serve unchanged upstream sources on loopback and block external page requests.
Use the installed Chromium, a one-window 1120x650 layout, a 16 MiB ordinary memory
budget and no optional image model. Choose an accessible renderer through the
declared largest-positive-CPU-delta rule over three seconds, lower-PID tie-break.
This selects a process candidate, not a controlling game object. Pass Anode's
already acquired lease identity/token only in the execution environment; require
both before launching. No manual screenshots, mouse interaction or game play.

The native input driver uses exact HWND/PID and session guards, 80 ms holds and
100 ms periods. Key lists are fixed before launch and never adapted to the oracle.
One initial pulse starts Tetris with Space. For the initial sixteen-moment pass,
deliver four pulses after moments 1–11, twelve after moment 14, none otherwise.
Pause and acknowledge the job before each between-capture burst, then resume.
Tetris gravity continues. Ended or constant games remain retained outcomes.

Choose the lowest-ID current active OCR track with at least ten readable values
and repeated contrast (second highest minus second lowest >2.2). If none exists,
abstain. Otherwise call start_change_search once with its scope and track; no
value, address, type, scale or layout is supplied. Let the product collect four
selection moments, delivering four fixed pulses after moments 1, 2 and 3 only.
The product must perform selection and schedule its fresh sixteen-moment job;
the evaluator must not call finish_change_search or submit that fresh job.

If the automatic transition overtakes polling of selection moment four, read
that state from the product's own memory-batch archive. This is not a replacement
capture. If selection abstains/refuses, retain it and stop discovery. Otherwise
use the same fixed sixteen-moment input schedule for fresh fitting/checking.
Reject skipped captures. Save separate initial/selection/fresh observations and
all selection receipts and witnesses. No seed or selection frame counts as a
fresh fitting or future-check frame.

One conditional location trial is allowed per game after the fresh pass. Among
current OCR checks, choose the lowest track ID having a candidate with exactly
four outcomes, all agrees; choose that candidate's lowest index. Derive the
requested value from the current track reading plus 10. Call prepare_probe once
with that check/index. If preparation refuses, retain it without fallback. If
prepared, verify target identity and a 1–8-byte patch, apply once, wait 750 ms,
observe_change, and attempt guarded restoration once. After successful restore,
wait 750 ms and observe_change again. No repeated writes, forced restoration,
extra probes or new candidate selection. During the trial the input driver stays
idle; natural game changes continue. On an exception, inspect status and attempt
restoration once only if the original trial is confirmed written and restoration
has not already been attempted. Unknown outcomes are not replayed.

The independent oracle reads displayed score/best (2048) or score/rows (Tetris)
through CDP DOM text/boxes, parsing numbers in Node outside the renderer. It reads
no numeric game variables or board/piece state. Runtime.evaluate reads generic
viewport/scroll geometry only. Use the unchanged 200 ms timing exclusion,
bracketing image requests with completed/beginning oracle requests, and spatial
track selection. Changed value/geometry, scrolling or missing coverage are
unscorable. Ignore child score-addition markup for numeric comparisons. Inputs
must match trusted browser key events. Instruments still add objects and overhead;
equal samples do not rule out ABA or observer artifacts.

For each attempted trial, separately bracket the complete prepare, post-edit
observe, and post-restoration observe RPC intervals with the DOM oracle. Apply
the same 200 ms request/gap bound and unchanged value/box/viewport requirement
to each counter. Retain stable displayed values or an unscorable reason. These
outer RPC intervals conservatively include image acquisition; they are not
atomic samples and this table does not automatically infer a causal effect.

Report discovery and trial outcomes separately. Four agreements or a displayed
response do not by themselves prove gameplay authority, internal-score identity,
effect scope, complete game-state restoration or hidden semantics. Byte restore
is not time reversal. Archive the final batch only when no trial is applied or
unresolved and the engine permits it, keep all
refusals, close only owned processes, and release Anode. Keep progress at 31%
unless separately justified capability/acceptance evidence warrants new credit.
