# Automatic descriptive memory follow-up selection

The core can select retained memory-proposal groups for a prospective check from
saved numeric trajectories and memory-read input coverage. No game-specific
profiles, screen labels or model calls are used. This is an investigation step;
it does not create gameplay names or editable controls.

`memory_input_contrast_v1` fits a direction for one sampled key per typed member.
It requires twelve source memory samples, at least two key episodes separated and
bounded by readable no-key intervals, a numeric change in every bounded episode,
and no changes during readable quiet intervals. Consistently increasing or
decreasing episodes pin that direction; differing or mixed directions pin only
change. Unknown and unbounded intervals are retained explicitly. Candidates whose
source mapping was invalidated cannot qualify. Groups keep all numeric rivals;
a group's best member determines its rank, so extra rivals do not add votes.
Up to four qualifying groups are selected automatically, with omission counts.
The existing explicit selection API still accepts up to eight groups.

Fresh outcomes never refit that expectation. A changed quiet interval, opposite
direction or constant bounded key episode contradicts it. Two agreeing episodes
and at least two unchanged quiet intervals are needed for consistency. Missing
coverage remains insufficient. Original two-level/order constraints and post-hoc
input associations stay separate. Every plan is persisted before releasing the
source batch and before fresh collection; result validation recomputes conditional
checks from its saved classes and values.

Planning reads the checksum-pinned proposal and archived manifest, not a target.
Read times are indexed once and shared across numeric rivals before checking each
member's availability. This avoids scanning all read receipts for every member.
Planning does not reverify the raw payload; fresh assessment does, through the
existing archive reader. The saved source/fresh hashes remain exposed through MCP.
Absent fields are omitted, preserving legacy plan/result replay bytes.

The desktop's initial broad automatic observation can continue once into twelve
visual-only fresh captures. It skips runtime inspection, rechecks, change searches,
existing findings/freezes, other jobs, invalidated scopes, human holds and cancelled
parents. Empty selection makes no batch change and starts no job. Stop during
preparation prevents child collection; Stop on a completed parent's active child
is redirected to that child through the existing job controller. A restart does
not restart this continuation. Explicit MCP planning/preparation uses the same core.

## Verification

Generated fixtures exercise source/fresh separation, quiet drift, reversal,
constant holds, missing boundaries, insufficient coverage, unknown preservation,
invalid pinned keys, tampered checks, no-input abstention, read-only planning with
a sealed target, automatic continuation exactly once, cancelled parents and
stopping during preparation. The generated end-to-end target uses 12 source and
12 fresh reads/images; planning adds none. Its initial key-linked pattern later
changes during a quiet interval and remains contradicted. No actual keyboard
sampler, game, production app, live model or upload is used.

Two full-suite attempts exposed inadequate generated input coverage: one pressed
poll at a release boundary, then a gap over 100 ms after adding endpoint polls.
Both correctly made selection abstain. The fixture now fills a single shared
sampled timeline and emits two explicit polls within each read. Production timing
and uncertainty checks were not relaxed. The failed logs and source archives are
retained alongside the final evidence. Strict Clippy also caught a complex return
type, resolved with an episode type alias.

The result index records final tests, exact replay and frozen snapshot checksums.
All artifacts remain local. The Windows-quarantined desktop preview has not been
restored, replaced or relaunched.

## Limits

Key intervals are observed polling summaries, not confirmed delivery, independent
trials or action meaning. Quiet means no sampled key, not absence of all inputs or
internal activity. Timing, hidden inputs, edits, drift and allocation reuse can
explain a pattern. Strong-looking coincidences can still pass these checks; no
causal, semantic or editing authority follows. Selection operates only on retained
proposal representatives, so earlier numeric/range/group omissions persist. The
strict quiet rule misses values that decay or regenerate while idle; twelve-sample
follow-ups can easily lack two qualifying episodes. Independent-game performance
is still unmeasured. The full-goal estimate stays 35%.
