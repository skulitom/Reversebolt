# Input delivery diagnostic v1

Before another memory-association run, compare the research runner's legacy
keybd_event call with the application's documented SendInput scan-code packet.
This diagnoses rendered response, not input meaning, actor identity or causality.
No target-memory discovery, naming, model call or field write is permitted.

Freeze this runner, the existing independent-runtime RPC helpers, the current
published application/MCP hashes and this protocol before launching Sable in
Anode. Retain a fresh pre-launch storage copy. Sable is a known development game.
Preserve the main desktop editor. At most four viewed setup screenshots and two
menu keys; no measurement image is manually viewed. Do not replay a started run.

Use the unchanged shared engine to attach with auto_observe=false and capture in
Play mode. One seed capture, then eight quiet/action pairs, then one final quiet
capture: eighteen images total. Quiet intervals and holds last one second each,
excluding capture time. Method order is legacy, SendInput, SendInput, legacy;
each method block uses D followed by A. This balances order partially but does
not reset the world. Input may change gameplay. Keys have no assigned meaning.

For each hold, require the exact selected window foreground and no conflicting
key. Poll every five milliseconds; stop on focus loss/foreign input and always
release the owned key. Record both APIs' packets, actual timing and sampled key
state; SendInput must accept one key-down and one key-up. Legacy return values
cannot establish delivery. Captures occur after release. No method or timing
changes after observing results, and no game settings changes.

Read the shared image/input evidence once all captures finish. Compare each
action's existing rendered-difference metric with the maximum of its adjoining
quiet intervals; retain absolute values and ratios without a semantic pass/fail
threshold. Also retain sparse patch displacement and unavailable matches. A
larger action change supports rendered response, not proof of player movement.
An equal/zero change can be a genuine no-op, an input failure or insensitive
measurement; do not promote it to proof that no relevant gameplay state exists.

After terminal completion, close only owned game/editor/runner processes, retain
save differences and backup, and release Anode. Keep all evidence local. Existing
image freshness, geometry and input limitations remain in force. No new model or
image algorithm is trained or tuned on this measurement.
