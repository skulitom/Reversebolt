# Reviewing parameters near observed activity

The shared core can now use validated repeated state associations to select
rooted contexts for a new metadata review. It reconstructs the original sibling
plan from discovery, recomputes every supplied response analysis, and rejects
changed plans, inconsistent observations, duplicated batches and wrong scopes.
Negative observations remain in the record; unobserved batches are explicit.

All responding paths seed the unchanged enclosing-role sampler. Nearby constant
fields remain eligible, but do not inherit the seed's observed activity, meaning
or editing authority. With no repeated associations, the review scope is empty.
The operation is read-only and does not bind an exited process to a new launch.

`runtime_inventory::for_paths` resolves exact selected paths from the report,
preserving original type IDs. It does not filter the original first-four-example
sample table: that could silently lose the specific object that responded.
Existing field eligibility and sample budgets still apply. The original full
catalog review remains available and unchanged.

The offline hypotheses CLI accepts `--focus MANIFEST`, where the manifest names
the original plan and ordered observation files. It saves the focused inventory,
recomputed analyses and scope before requesting inference. It then uses the same
default parameter-selection and proposal prompts as ordinary metadata naming.
This mode is not yet wired into automatic desktop/MCP investigations; it is a
shared core capability with a saved-data evaluation entry point.

## Frozen development result

The [protocol](PROTOCOL.md) and exact sources, executable, input observations and
model identity were frozen before one review of the retained Sable run. No game
launch, process-memory operation, input, image capture, manual image review or
field write occurred. All local artifacts are under
`test-results/runtime-activity-focus-v1`.

The two repeated associations selected two rooted roles. Their complete observed
neighborhood contained 26 scalar paths across four declaring types, with no
neighbor or sample omissions. The original two unmeasured activity batches remain
unobserved. The model selected two types, then returned empty proposals for both.
There were **three model requests, zero accepted proposals and zero rejected
proposals**; total recorded request time was 20.945 seconds. The largest prompt
was 4,732 bytes. No retry or prompt adjustment followed the abstention.

This narrows the evidence to particular observed contexts, but it does not show
that useful controls were found. Most of these labels describe internal state;
the absence of proposals does not prove that all 26 fields are useless. Likewise,
the earlier state associations do not establish player identity or causality.

The next search should examine reference relationships from these active roles:
adjustable settings can live in separate objects. That requires explicit
relationship evidence and bounded coverage, rather than transferring identity
or meaning to every object of the same type. Any proposed parameter still needs
an appropriate activity, measurable outcome and a bounded intervention with
restoration before it can become a verified control. Current paths belong to the
exited process and require fresh discovery for a live experiment.
