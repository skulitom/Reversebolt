# Exploratory text-only runtime naming

The preceding turn delivered shared periodic value holds and a measured reversible
Manifold Garden input-response contrast. It was progress. Meaningful automatic
selection and explanations remain missing: readable identifiers alone are not
gameplay understanding.

Use retained discovery reports, an already-installed local model and no game
source, offsets, profiles, screenshots, input or memory writes. Build a compact
inventory of types with actual scalar reads, excluding only the report's declared
core library. Present every retained non-core type, with short field samples;
record omissions and prompt limits. Do not keyword-search for the field already
tested in Manifold Garden.

First ask the model to select promising types. Then present observed fields for
those types and request up to twelve plain names, short cautious explanations and
exact evidence references. Outputs must reference actual observed fields; names
and values are untrusted data, not instructions. A model proposal never establishes
an effect, persistent identity, range, or authority to write. Invalid/truncated
output is a failure, not an empty successful result.

Run first on the retained Manifold Garden gameplay report, then unchanged on the
retained Blue Prince menu report to inspect selection quality and abstention. This
is exploratory saved-data evaluation, not a withheld generalization test. The
earlier measured walking field can check whether automatic selection reaches a
known useful candidate, but cannot grade all new descriptions. Retain exact
prompts, model digest, server version, options, raw responses, accepted and rejected
items, elapsed time and source hashes. Promote to the product only if this improves
the user-facing selection without inventing verified meanings.
