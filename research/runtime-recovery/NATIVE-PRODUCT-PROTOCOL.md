# Newly retained route, full restart, product recovery

This is a prospective integration evaluation on the known Viewfinder development
game, not an unfamiliar-game or semantic validation. Freeze this protocol, runner,
audit, Rust sources, published binaries and generic recovery CLI before launch.
Back up local game storage. Preserve the user's main editor and Steam session.

Use two fresh, owned Anode game processes and one new durable engine data directory.
Allow at most three viewed setup images and two menu actions per process. Use no
manually reviewed measurement images and no model calls. Stop on unavailable,
ambiguous, malformed or uncertain evidence; never repeat an uncertain input/write.

1. In the first fresh process, discover with the published product. Bootstrap the
   investigation using the generic declared-route proposal from the sole earlier
   positive comparison and its archived discovery, without choosing a field by
   manually supplied label, address, offset or source layout. The historical test
   is never imported into product storage. Select the exact freshly proposed ID.
2. Prepare one new comparison with the earlier question, value and four-action
   sequence. The product must save its own new recipe during preparation. Require
   a useful six-image baseline before one edit; collect six changed images,
   restore exact original bytes, then collect six restored images. Retain failure.
3. Close only the owned game and engine after confirming restoration. Start a
   different game process and reopen the same engine data directory. Check boot
   and process identity changes. Discover without naming/model calls.
4. Automatic discovery must independently recheck the newly saved comparison and
   show one fresh candidate with a needs-revalidation hint tied to that source.
   No source locator scope substitution or research backfill is permitted here.
   Invoke the shared recover_runtime_control command once and check it returns
   the same candidate and a fresh preparation template.
5. Supply new test/change UUIDs to that template and conduct one further bounded
   before/change/restoration comparison through MCP. This independently rechecks
   the effect; automatic recovery alone is not an effect claim or edit authority.

Audit exact recipe/test/report bindings, both fresh process scopes, durable reopen,
MCP receipts, input action receipts and actual sampled windows, all image hashes,
helper unload, value readbacks, chronology and exact restoration. Independently
measure full-frame grayscale differences without changing thresholds or dropping
frames. Compare backed-up save/backup hashes. Close owned processes and release
Anode. A failure at either stage remains evidence and prevents the next stage.

This proves only what is observed for the tested action sequence. Persistent actor
identity, semantic names, physical units, derived relationships, complete world
rollback and independent-game generalization remain outside this result.
