# Two automatically checked native values

Freeze this protocol, runner, owned fixture, changed source snapshots and exact
binary hashes before either case. Run two fresh Anode sessions against an owned
WinForms fixture. Its two independent float fields occupy randomized locations;
the product receives neither the source layout nor oracle addresses. The fixed
sixteen paired values contain independent training sequences followed by a hold
and distinct change for each field. Numbers are drawn in separate screen regions.

Attach through MCP with a 32 MiB budget and local model disabled. Use the normal
automatic sixteen-capture job; no capture, correlate or start_prediction_check
commands. After each completed capture, the evaluator supplies the next fixed
pair to the fixture. Retain missed captures, uncertain readings and failures;
do not rerun or change candidate selection. Verify both tracks automatically
freeze at twelve and retain unchanged mappings for captures thirteen–sixteen.
All candidates share the existing 200-interpretation read budget.

Sort the resulting two checks by the observed track's vertical screen position,
not by their memory address or oracle value. Prepare candidate zero of each check,
requesting its latest observed value plus three. The evaluator verifies only that
each proposed patch is confined to the corresponding owned field. If either
proposal is unavailable or falls outside it, retain the refusal/failure and do
not choose another candidate. Preparation alone never authorizes another write.

Case zero applies the upper card's reviewed proposal; case one applies the lower
card's. Apply once, retain the automatic result, wait 200 ms and observe explicitly.
Require the selected value to follow while the other field stays unchanged.
Verify that both passive checks were invalidated. Request application of the
other already-prepared plan and require expiry before native entry; the fixture
oracle must still show only the selected field changed. This is a guard test on
owned disposable fields, not a second intended intervention.

Attempt one guarded restoration of the selected change and verify both oracle
fields return to their pretrial values. Never force or retry restoration. One
checked cleanup is permitted only if an exception follows a confirmed write
before restoration was attempted; unknown write outcomes never authorize retry.
Close only owned fixture/engine/MCP processes and release the seat after both
terminal outcomes. No UI input, screenshots reviewed by a person, or gameplay.

This tests automatic multi-series collection, distinct check/card identities and
trial routing in a controlled native fixture. It is not independent-game
generalization, semantic discovery, an atomic snapshot or evidence that hidden
and downstream effects are completely observed or reversible. Preserve all
failed cases and their exact method; audit the artifacts after the runs.
