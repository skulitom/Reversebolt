# Automatic prospective numeric checks

Freeze product binaries, changed source snapshots, runners and configuration
before any native run. Do not revise this method based on an outcome, replace a
selected candidate, or rerun a failed case. Retain all errors and abstentions.

First run one owned two-location WinForms fixture through default automatic
attachment with local vision disabled and a 32 MiB memory budget. The fixed
sixteen-value sequence is in the configuration. The evaluator changes fixture
values between captures, observes progress, and checks the resulting snapshots;
it sends no capture, comparison, prediction-check or write command. The source
and unused-copy addresses are randomized and never passed to Reversebolt.
Verify automatic freezing after twelve captures, immutable predictions through
four later readings, original image/read timing witnesses, no change journal
entries and no captures beyond the sixteen-moment job. This is controlled
integration, not independent-game generalization.

Then run one fresh 2048 session and one fresh Javascript Tetris session, in that
order, using the unchanged original source already retained by the independent-
game baseline. Use new browser profiles, blocked external requests, local-model
disabled, the frozen input schedules and the same observation budget of 16 MiB.
Select the accessible renderer with the largest positive CPU-time delta over
three seconds, PID as tie-break, as an evaluation setup step. Do not infer a
gameplay role from this choice. Attach to that scope with automatic observation
enabled, then only poll its default sixteen-capture job. The engine must choose
and start any prospective check itself. Do not manually freeze a track or issue
edits. Preserve absent/contradicted/invalidated checks as actual results.

Reuse the capture-alignment scorer unchanged: independent DOM oracle bounds and
values, image intervals, fixed 200 ms oracle timing limit, explicit unscorable
moments, and the previously defined geometry matching. Oracle data and game
source never enter the product. Audit delivered input, source identities,
immutable hypotheses, before-image witnesses and later evidence. The games are
already exposed development evaluations, not a withheld acceptance test. No
automatic selection, visual agreement or unchanged value establishes a verified
gameplay control or overall goal completion.

No manual screenshot review or game operation is required. Close only owned
processes and release the Anode lease. Report performance, failures and remaining
limits, including one selected numeric series per bounded batch and the fact
that ranking estimates investigation effort, not user importance.
