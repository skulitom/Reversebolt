# Renderer-scope numeric discovery check

Freeze the published product, unchanged upstream games, input schedule and this
method before capture. Run one fresh profile each of original 2048 and Javascript
Tetris, in that order, in Anode. Use the ordinary 30-tool MCP API and 16 MiB per
capture. Disable optional local image interpretation to isolate numeric discovery.
Keep the existing fixed 80 ms native input pulses every 350 ms; do not adapt them
to values, outcomes, or the oracle. Preserve every attempt and failure.

Choose the browser's window normally, attach without automatic observation, and
start the fixed input driver. Over three seconds, measure Chromium's reported
CPU-time deltas. Among accessible descendants identified by Chromium as renderers,
select the greatest positive delta, breaking ties by smaller PID. Record the
whole inventory and both CPU samples. No oracle value, game source field, address
or known memory layout enters this decision or the product. This is an explicit
browser-specific experimental selection rule, not a general automatic source
selector or proof that the selected process owns gameplay state.

Reattach with that child's exact creation identity and the original window.
Start a 12-capture full-observation job, with comparison enabled. On completion,
select the active OCR track with a nonempty match list and the lowest track ID.
Freeze its mappings before starting a four-capture job without comparisons.
If no track has matches, record that failure and still collect the four fresh
captures. Do not refit, select another track, retry failed captures, or write
memory. Keep source identity and exact frame provenance with every result.

Use the separate existing oracle and selected-counter scorer only after capture,
with its unchanged 200 ms timing/geometry exclusions. Neither the oracle nor
labels are supplied to Reversebolt. Retain wrong/conflicting/missing readings.
After saving the final state, archive the memory batch through advance_memory
without automatic capture, retaining the exact selected region/chunk plan.
An archive failure remains explicit rather than changing the captured result.

Report numeric matches and fresh prediction outcomes separately from OCR scores.
CPU activity, correlation and even fresh prediction agreement do not establish
authority, gameplay meaning, or editability. Oracle instrumentation can allocate
copies. These are two exposed development games, not withheld release acceptance.
Keep overall progress at 26% unless a separately implemented and verified
capability justifies additional credit.
