# Passive play observation verification

Freeze product binaries, sources and this evaluator before running. Use the
existing owned ABI/visual fixture in Anode, not a game. No model calls, game
profiles or gameplay memory writes are needed. This is integration evidence,
not independent generalization or proof of button meanings.

Verify that automatic attach collects fifteen image/input captures before one
runtime discovery, with no capture memory reads or OCR. Then reconnect without
automatic observation, discover/refresh the fixture's observed WalkSpeed field
solely to configure the existing test renderer, and collect fifteen play-mode
frames. The evaluator supplies D holds after frames 2, 4, 8, 9 and 12, and a D+A
chord after frame 6. Each hold is 200 ms; capture delays are 500 ms. No input is
sent until the fixture's actual window is confirmed foreground in the seat.

The shared MCP read_play_evidence call must return retained, image- and
metadata-bound intervals; repeated key episodes; quiet intervals; and an unknown
chord interval. At least two bounded key episodes must show a nonzero rendered
response above 3 grayscale levels while quiet median remains below 1. This tests
association plumbing only. Continuous sampled key intervals must not become
independent episodes. No executable action plan or semantic label is expected.

Check wrong investigation/batch, reversed/duplicate frame IDs and altered saved
image rejection. Restore the deliberately altered fixture image immediately.
Keep the failing attempt if any check fails; do not adjust thresholds or repeat
uncertain input. Record helper completion, retained evidence, process exit and
absence of writes. Close owned processes and release the seat. Use no screenshots
for manual review; focus through accessibility when required.
