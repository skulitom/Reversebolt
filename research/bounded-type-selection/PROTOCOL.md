# Bounded type-selection convergence

The retained Vampire Survivors V2 run reached native metadata but failed naming:
364 types became 30, 18, 12, then 10 after twenty model requests. Each page asked
for eight nominations independently; the final union never reached eight. Keep
that original failure and its frozen reader, inventory and receipts unchanged.

Give complete pages explicit nomination allowances enforced in the prompt,
response schema and local validation. Once there are at most eight pages, share
eight slots evenly across them, redistributing capacity unused by small pages.
Ordering breaks ties. Earlier rounds keep every page, with at most eight or half
its rows (minimum one), whichever is smaller. Empty nominations remain valid.
Keep four rounds, 24 selection requests, 12,000 prompt bytes and existing model
contexts/output limits. Do not trim field labels or transfer object text between
paths. Historical receipts without quotas remain readable.

This is a bounded selection heuristic, not a global ranking guarantee. Good
candidates can cluster on one page and be lost to its allowance; order can affect
selection. More than eight inseparable singleton rows can still fail rather than
silently dropping pages. Tests must retain budget/foreign-ID/duplicate/oversize
refusals and demonstrate that a small multi-page pool reaches eight even when
every allowance is filled. Do not increase a budget to force this case through.

Freeze the revised observer-only evaluator, Rust sources, this protocol, scripts,
inputs and installed local model before inference. Reuse existing baseline
receipts; never repeat them to choose a better output. Run exactly once each:
the failed Vampire V2 report, the previous `latest` gameplay report, the menu
report, the owned context fixture and the opaque-label variant from the prior
object-label-selection experiment. The four older baselines predate other
product changes, so their differences cannot isolate this quota change. No
game-specific ranking, manually selected field or candidate rescue is allowed.

Use the existing full `reversebolt-runtime-hypotheses` evaluator without activity
images. Check the rebuilt Vampire inventory against the original before accepting
the result. Retain every request, nomination, rejected question, abstention and
failure. Check each complete type row, exact path-scoped text, prompt hash, model
digest, quotas and input-token headroom. Report both selection convergence and
accepted/rejected questions with their actual labels; acceptance is reference and
lexical validation, not semantic correctness or edit authority. No game launch,
input, process memory access, screenshot or write is needed for this replay.

The desktop preview may be updated after the workspace checks, frozen replay and
packaged startup/MCP checks. Preserve the user's existing editor. No independent
