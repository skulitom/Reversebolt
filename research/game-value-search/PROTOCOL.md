# Value-guided search on unchanged independent games — frozen v1

Run one fresh owned profile each of original 2048 and Javascript Tetris, in that
order, inside Anode. Use the exact upstream revisions and file hashes retained
by independent-games, and the unchanged published product 105104. Freeze this
method, input driver, runner, numeric scorer, oracle helper, source pins and
executable hashes before either game. Retain all failures; no retries, replacement
tracks or altered schedules after results. These are exposed development games,
not withheld acceptance.

Host original files on loopback, block external page requests, disable optional
local image interpretation, and use the normal 16 MiB memory budget. Select the
owned browser window normally. Choose an accessible renderer by greatest positive
CPU-time delta over three seconds, smaller-PID tie-break. This browser-specific
evaluation rule identifies a process candidate, not gameplay authority. Neither
the oracle nor known source fields/addresses/layouts are supplied to the product.

Attach normally for sixteen automatic moments. Between completed captures, pause
the observation job and acknowledge it, deliver a fixed native-key burst, then
resume. Each stage uses four pulses after moments 1–11, twelve after moment 14,
and no other bursts. The initial driver supplies one pulse (Space starts Tetris).
Use the frozen cyclic key lists, 80 ms holds and 100 ms periods; never adapt to
the oracle or play outcomes. Tetris gravity continues throughout. Each pulse
requires the exact owned foreground HWND/PID and correct child session, releases
its key, and is matched against trusted browser keyboard events. No manual input.

After the first stage, choose the lowest-ID active OCR track with a current
finite reading, at least ten usable readings, and repeated contrast: the second
highest minus second lowest exceeds 2.2. If none qualifies, record abstention.
Otherwise call search_number with that observed scope/track, without supplying a
value or address. No input burst occurs during the search. If it finds no areas,
retain the refusal and existing evidence. If it starts a new batch, collect its
normal sixteen automatic moments with the same fixed burst policy. New fitting
and fresh prediction outcomes remain separate from the old seed/history.
Do not manually correlate, freeze, retry a capture, change candidate selection,
submit oracle observations, or write memory. Archive the final batch if possible.

The evaluation oracle uses CDP DOM.getOuterHTML and DOM.getBoxModel to read the
displayed score/best (2048) or score/rows (Tetris). Parse numbers only in Node,
outside the target renderer. Runtime.evaluate reads only generic viewport/scroll
geometry, never game variables or numeric counter values. Native-key listeners
record event receipt. These instruments still add overhead and native/JS objects;
they do not prove the absence of observer artifacts. Actual internal game scores,
tiles and piece state are not read in this evaluation.

Poll the oracle with 50 ms delays after completed requests. Score using the
200 ms timing exclusion and spatial track selection, with current image
request bounds. Bracket each image with a completed oracle request before its
start and an oracle request beginning after its end. Missing coverage, scrolling,
changed values/geometry and browser/
client mismatch are unscorable, never counted correct. Ignore changing score-
addition child markup when comparing counter values; retain raw HTML separately.
Report wrong, conflicting, missing, correct and unscorable outcomes by stage.
CDP text and geometry reads are sequential; equal samples cannot exclude ABA.

Record selected-process inventories, input order, all capture states, search
selection receipts/windows, requested/read/retained bytes, source image identity,
old/fresh frame IDs, frozen candidates and each prospective outcome. Broader
coverage and predictive agreement do not establish a controlling value, hidden
semantics, editable gameplay or successful restoration. Keep progress at 30%
unless a separately implemented capability is verified; no fixture/game name,
known offset or source-derived representation may repair the product result.
