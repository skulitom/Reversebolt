# Native result-capture persistence checks

Freeze method, original owned fixture, source snapshots and binary hashes before
any case. Run exactly three fresh cases in Anode, all through MCP. Reuse the
two-field randomized WinForms fixture from location-probes without modifying it.
Keep the prior sixteen training/fresh values, 32 MiB observation budget, no
local model, lowest active numeric track with matches, candidate zero and desired
53 from observed 50. Never replace a refused candidate or rerun an observed case.
Oracle addresses stay in the evaluator and only check the selected patch is
within an owned fixture field; do not pass them to the product.

Case 0: lower field drives display. Case 1: upper field drives display. Apply
once, wait 200 ms, explicitly observe, then attempt one guarded restoration.
Read both scalar fields from the independent fixture oracle. Expect matched
visible response for a selected source and no visible response for a selected
copy, with expected whole-interpretation bytes at both capture endpoints.
After successful restoration wait 200 ms and observe again.

Case 2: upper field drives display. Apply once and retain the automatic result.
After confirming both the byte write and oracle fields, issue the fixture's
ordinary external-update command 47. Wait for its oracle to acknowledge both
fields are 47, then 150 ms before explicit observation. This is an evaluation-only
controlled overwrite, not a discovery hint or simulated successful product
write. Expect memory_changed, unavailable conditional probe comparisons, and a
refused restoration that preserves the new 47 values and original write receipt.
Never retry or force restoration. A one-time guarded cleanup is permitted only
if execution was interrupted after confirmed writing but before any restoration
attempt. Uncertain writes never authorize cleanup writes.

Each run checks session identity, retains failures and closes only owned fixture,
engine and MCP processes. No UI inputs, screenshot review or gameplay are needed.
This verifies native read/capture/write integration in a controlled fixture, not
gameplay authority, absence of delayed/hidden effects, ABA-free continuous value
retention or independent-game generalization. The earlier Tetris result cannot
be retroactively classified with memory evidence it did not collect.
