# Product-owned input during response comparisons

Freeze sources and product binaries before starting the owned native fixture in
Anode. Reuse the previously built, explicitly labelled ABI fixture and record its
hash. The fixture is not an independent game or evidence of semantic discovery.
The evaluator selects the observed WalkSpeed label and a D/A/D/A, 200 ms plan.
The product must execute all holds through the actual shared MCP option;
the evaluator must not inject gameplay keys.

Run one complete baseline/edit/recovery comparison, with six engine captures
per condition. Check sampled input witnesses, suppression assessment, original
bytes through the fixture oracle, source hypothesis retention and durable input
intent/outcome receipts. Repeat stale observation requests and require no new
input intents or captures. No manual screenshot review.

Prepare another test, focus a separate owned fixture window, and request one
automatic step. Require refusal, no accepted keydown, and a stopped test. Restore
fixture focus through its own setup API.

Prepare a third test and collect its two idle frames. Start the planned third
step asynchronously. Once the independent evaluator sees D down, terminate only
the owned headless editor. Require the bounded input worker to release D, save a
failure receipt and exit. Restart the editor and require a stopped pending test;
the original request must not replay. Preserve the successful earlier comparison.

Retain failures and unknown outcomes without retrying inputs. Close owned test
processes and release Anode. This validates opt-in shared-engine action execution
and recovery, not learned controls, action meanings or game generalization.
