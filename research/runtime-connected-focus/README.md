# Following recorded connections toward adjustable settings

The shared core can now extend an activity-focused investigation to immediate
parent and child contexts on the observed rooted routes. It retains the exact
member path, direction and discovery snapshot for each relationship. Embedded
fields stay inside their enclosing object; array elements remain separate
contexts. Same type names, values and addresses do not create connections.

The operation replays the original state-response evidence first. It then reviews
connected contexts separately from the responding contexts already examined.
Roles are selected in native candidate traversal order, with at most 32 roles
and the existing 128-path sibling sampler. Role/field omissions remain explicit;
more than 1,024 connected roles fails. Duplicate snapshot IDs and unsupported
cross-snapshot relationships are rejected. Noncanonical graph edges, alias joins
and objects not present in the discovery are not covered by this implementation.

The saved-data CLI exposes this as `--focus MANIFEST --connected-focus`. Default
same-context review remains unchanged. Automatic desktop/MCP use of either focus
mode remains unfinished; no new control is published by these operations.

## Frozen connected-context review

The [protocol](PROTOCOL.md) used the same retained Sable discovery and all eight
completed activity batches. The target was already exited. Exact sources, input
files, executable and model identity were frozen before one local review, with
no new game launch, memory operation, input, capture, manual image viewing or
field write. Artifacts are in `test-results/runtime-connected-focus-v1`.

The two responding paths led to six immediate connected contexts containing 145
eligible scalar paths. All six roles were selected; 128 paths fit the fixed field
budget and 17 were omitted. The naming inventory retained 116 path samples:
six selected paths were core-library fields and six exceeded existing per-field
sample limits. The original two unmeasured response batches remain unknown.

The unchanged model prompts selected the observed CharacterConfiguration,
ClothingItem and controller types. Four requests took 30.050 seconds in total;
the largest prompt was 36,101 bytes. The configuration and clothing groups
abstained. The controller group proposed two questions, about maximum ground
incline and swimming depth. Both were rejected because each alternative list
also included its own primary candidate ID. The original result remains
**zero accepted, two rejected**, with exact outputs and reasons preserved.

An independent audit reproduces rooted role identities and parent/child links
from the retained metadata, verifies same-snapshot provenance, original type IDs,
exact response analyses, input/source hashes, model identity, request context
limits and sample omissions. It passes without game or model access.

## Separate cleanup replay

The [subsequent protocol](CLEANUP-PROTOCOL.md) addresses the observed structural
error without requesting another model answer. A new core normalization removes
only one exact primary ID from an otherwise bounded, unique alternatives list,
then applies the unchanged strict validator. It retains the original batch and
every removed proposal/alternative index. It does not repair names, citations,
unknown paths, duplicate distinct alternatives or oversized lists.

The shared observer records this cleanup beside its raw model stages in future
reviews. Strict validation itself still rejects self-alternatives, so other
callers do not silently change behavior. Older receipts remain readable.

A separately frozen replay reconstructed the original proposals from model
stages and first reproduced the original rejected batch. Removing the two exact
self-references produced **two accepted investigation questions, zero rejected**.
Both retained all original wording, citations, primary paths and distinct
alternatives. The original receipt was not edited. Its separate cleanup artifact
and independent audit are in `cleanup-replay/`. No inference or target access
occurred during cleanup.

Acceptance here means structurally and lexically grounded questions. It does not
verify the proposed slope or swimming behavior, player identity, current object
occupants or an effect from editing. Discovery relationships predate the input
observations. A later live experiment needs fresh paths, an appropriate activity
and a measurable predicted consequence, followed by restoration. Neither question
is a verified control, and neither has been shown in the user's app.
