# Same-process rechecks — frozen protocol v1

Two predetermined runs in separate owned WinForms processes inside Anode. No
manual screenshots or gameplay. The unchanged two-field fixture is copied from
multiple-checks. Each run starts with sixteen automatic discovery moments and
the original protocol's two independent numeric sequences. Slot 0 edits the upper
field; slot 1 the lower. Both require a matched effect, refusal to recheck while
the trial is applied, and successful restoration. The other prepared plan expires.

Then call recheck_findings once with default automatic observation. All hypotheses
must remain unchanged, linked to archived evidence, with empty fresh samples.
Exactly four captures and at most eight bytes per interpretation are planned.
Slot 0 uses [54,64], [54,64], [50,43], [50,43]; slot 1 stays [50,43] four times.
Both require four correct OCR readings and unchanged predictions; a stale batch
replay is refused. Slot 0 must prepare, apply, observe and restore an edit on the
other field. Slot 1 must refuse preparation for lack of fresh contrast.

The evaluator changes fixture values only after completed captures and checks
their private allocation oracle only outside the product. Product inputs are
window/process identity, a 32 MiB discovery budget, and ordinary trial requests;
no offsets, type/layout, oracle or game profile are given. No manual capture,
correlate or prediction-freeze calls. No LLM calls. No retries or replacement
runs after observed failures. Preserve raw output and strict OCR failures.

This validates a controlled same-process workflow, not independently implemented
games, restart/relocation recovery, semantic naming or gameplay authority.
